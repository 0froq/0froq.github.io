# froQ public site critique

Target: whole public Nuxt site (`app/pages`), homepage primary. Not froq-api.

## Design-specificity verdict

**Authored for this product**, not a theme you could drop onto another blog — with one structural hole.

The first screen (sticky `h-svh` pane, left `SvgFroqLogo` + short prose, three `SiteRailLink`s in the right gutter, `↓ scraps` + flush `AppFooter`) is a signature, not a feed hero. The scrapboard (seeded `InkDots` / `InkRing`, fold, inline recs) is a private-notebook gesture. Inner `IssueReading` sheets feel like an issue, not Medium. Paper/ink tokens, EB Garamond + CJK, pencil underlines — this would look wrong on a SaaS marketing site.

The hole: **the first viewport does not deliver the product success criterion.** PRODUCT.md wants a visitor to know, without finishing the page, what the author is currently thinking and making. What ships is an English bio (“Hola! I'm froQ…”) with the Chinese draft commented out in `docs/index.md`. Current work lives below the fold in scraps.

## Emotional journey

Intended peak: logo, wry rail notes, then the scrapboard as a desk you were allowed to see.

Actual first 10 seconds: English grad-student bio. No current project. The product promise waits on `↓ scraps`.

Valley 1: `/posts` — giant “Posts,” leaking `==代序==`, “从右侧选一层。”, no articles.

Valley 2: `/corpus` — six Latin names + leaking `:::warning`. First-timers bounce.

Valley 3: `/dashboard` titled **Notes**, body “Dashboard is not ported yet… `docs/dashboard/`.” Honest, but a ticket, not an empty desk. Peak-end: last stop is unfinished infrastructure.

Recovery: article pages (`IssueReading`) and scrap folds. Those still feel like this person.

## Strengths

1. **Home composition is a real signature.** Sticky full-viewport intro, left logo + prose, section routes only in the right rail, scraps as a second sheet. Matches the brief; not a feed.
2. **手绘 is seeded SVG**, not icon-font cosplay: `InkDots` / `InkRing` on scrap folds, pencil underlines on rails.
3. **Article reading is the most resolved surface.** Sticky header (logo, section / layer, truncated title) + calm issue sheet. Chinese long-form actually reads.

## Priority issues

### P1 — First screen is a bio, not the index of now
- **What:** Home markdown is English identity copy; Chinese version commented out in `docs/index.md`. Current thinking is in `HomeScraps`, below `↓ scraps`.
- **Why:** Success is “without finishing the page, know what the author is thinking and making.” First-timers never get there. Chinese-primary rule is broken on the most important viewport.
- **Fix:** One current sentence (or one pinned scrap) in the first viewport, in Chinese. Bio secondary. Restore the commented Chinese home as primary voice.
- **Command:** `/impeccable distill` (first-screen message) and `/impeccable layout` (place a now-signal in the signature pane)

### P1 — Hubs hide the writing
- **What:** `/posts` and `/corpus` show `SiteHub` + intro + rails, then “从右侧选一层。” Index pages are empty on purpose.
- **Why:** An issue-style index should still index attempts. This is a locked table of contents.
- **Fix:** Show a small editorial set (latest or pinned across layers) *and* the layer rail. Empty instruction only if a layer truly has zero entries.
- **Command:** `/impeccable layout`

### P1 — Hub markdown is leaking
- **What:** Live `/posts` shows `==代序==` / `==成言==` / `==前脩==`. Live `/corpus` shows `:::warning 免责声明` through `:::`.
- **Why:** The one place that should explain the taxonomy looks unfinished. Destroys trust before a single article.
- **Fix:** Enable mark + containers in Content, or stop using syntax the renderer does not support.
- **Command:** `/impeccable polish`

### P1 — Naming is three products stitched together
- **What:** Home rail: Posts, Corpus, Dashboard. `AppHeader`: Writing, Corpus, Notes. `SiteHub` title: Posts. Dashboard `h1`: Notes. Document title on `/posts`: Writing.
- **Why:** Users should not wonder whether Posts and Writing are the same place. Dashboard vs Notes is worse.
- **Fix:** One word per layer everywhere. If the public name is Posts / Corpus / Dashboard, the header crumb must say that.
- **Command:** `/impeccable clarify`

### P2 — Corpus rail is a Latin wall; scrap reactions are invisible
- **What:** Six literary-pathology names; notes hidden on small screens. Scrap emoji picker exists only on `contextmenu`.
- **Why:** >4 options + jargon + no note on mobile. Casey cannot right-click.
- **Fix:** Cut or group Corpus to ≤4 visible choices; always show the Chinese note. Put one reaction affordance on the scrap row.
- **Command:** `/impeccable distill` + `/impeccable onboard`

## Minor observations

- Theme toggle uses Phosphor, not Ink*.
- `AppNav.vue` duplicates the three links and is unused.
- Issue lists are `created DESC` — chronological dump vs “index, not feed.”
- `color scheme auto` can invert the paper identity into a generic dark portfolio (live capture was on auto).
- Detector CLI (`detect.mjs` on pages/components/layouts/css): **0 findings**. The authored look evades generic slop rules; the real problems are IA, copy, and render bugs the regex engine does not see.
- Browser detector overlay: Assessment B could not hold a tab (MCP tabs vanished). Parent later opened `/`, `/posts`, `/corpus`, `/dashboard` without injection. **No user-visible overlay.** Do not look for highlights in the browser.
