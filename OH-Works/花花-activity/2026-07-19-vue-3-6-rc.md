# Vue 3.6.0-rc.1 发布 — Vapor Mode 功能完备

**发现时间**: 2026-07-19 08:00 (巡检)
**发布时间**: 2026-07-18 09:12 CST (UTC 01:12)
**状态**: 从 beta.17 (06-24, 24 天) → RC.1

## 核心变化

### 1. Vapor Mode 功能完备
- 新的可选编译模式，目标：减少基线 bundle 大小 + 提升性能
- 语法入口：`<script setup vapor>`、`<template vapor>`
- `createVaporApp()` 纯 Vapor 应用入口（不含 VDOM runtime）
- 支持 Composition API + `<script setup>`；不支持 Options API
- 与 Solid / Svelte 5 同级别的第三方 benchmark 表现

### 2. Reactivity 重大重构
- `@vue/reactivity` 基于 [alien-signals](https://github.com/stackblitz/alien-signals) 重写
- StackBlitz 出品，显著改善性能与内存占用
- 这是 Vue 3 响应式系统自诞生以来最大的底层变更

### 3. VDOM Interop 插件
- `vaporInteropPlugin` 允许 Vapor/VDOM 组件互相嵌套
- 覆盖标准 props/events/slots
- 建议保持渲染模式区域分离，避免深层混合嵌套

### 4. 特性差异
- Vapor 中 `slots.default()` 是有副作用的调用，不能用于 dry run
- 自定义指令接口不同：函数签名 vs 对象钩子
- 事件委托到 `document`（`stopPropagation()` 会影响委托事件）
- 不支持：Options API、`app.config.globalProperties`、`getCurrentInstance()`（返回 null）、`v-memo`、`$el`/`$props` 等实例属性

## 对 blog 项目的影响
- VitePress 2.0 仍 alpha.18 (07-06)，尚未升级到基于 Vue 3.6
- Vue 3.6 RC 稳定后，VitePress 2.0 正式版可能会跟进
- alien-signals 重构的 reactivity 理论上会改善 SSR hydration 性能
- 在 blog 层面，暂时不需要关注 Vapor Mode（VitePress 使用 VDOM 模式）
