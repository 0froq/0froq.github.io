## CHANGELOG 要点（rc.2 → rc.3，5 commits 后又有新 commit 进入 main）

绝大多数条目集中在 **compiler-vapor / runtime-vapor**：

- **compiler-vapor**：falsy hidden bindings 折叠进静态模板；v-model 在 prop effects 之后生成；引号属性值后空格保留；缓存 member expression 中的可选链；自定义指令值包括号。
- **runtime-vapor**：app unmount 生命周期与 vdom 对齐；v-show source / transition hooks 不再在 fragment effects 中被追踪；teleport target 在 scope 销毁时清理；KeepAlive 分支移除延迟到 cache pruning、async setup pending 时延迟更新；自定义指令在 async component / fragment root 上的处理；interop 场景下 vdom props 归一化保留；并发 async hydration context 恢复等。
- **compiler-sfc**：避免遍历缓存的类型引用（#15175）。

## 信号解读

1. **Vapor Mode 进入密集 bugfix 阶段**。rc.3 的改动几乎全是 Vapor 相关修复，说明功能集已冻结（beta.1 时宣布 feature parity），当前在做正确性打磨。这类「行为对齐 vdom」的修复（unmount 生命周期、hydration、KeepAlive、interop）通常出现在临近 stable 之前。
2. **rc.2 → rc.3 间隔 20+ 天**，节奏偏稳。若后续 rc 间隔缩短并出现 release candidate 收尾，3.6 stable 可能在秋季（对照 Vue Amsterdam 3 月的节奏预期）。
3. **对 froq.me 的潜在影响**：博客基于 VitePress（当前仍 alpha.19 线），VitePress 2 本身走 Vapor 实验路线。Vue 3.6 stable 落地后，VitePress 2 升级路径会更清晰，可届时一并评估。
