# 2026-05-30 终端与编辑器生态动态

> 凌晨巡检整理。前几轮覆盖了前端工具链、CSS、气候数据、字体设计，这轮回到蛙蛙的日常环境本身——Neovim、Ghostty、Zellij。2026 年 3-4 月这个生态发生了不少结构性变化。

---

## 一、Neovim 生态：AI 插件、Treesitter 迁移、包管理

### 1. AI 插件双雄：avante.nvim vs CodeCompanion.nvim

2026 年 Neovim AI 插件领域形成两强格局，哲学差异明显：

#### avante.nvim（17K+ stars）
- **定位**：Cursor inside Neovim。选中代码 → 快捷键 → 描述需求 → sidebar diff → accept/reject
- **工作流**：显式、审慎、diff-first。适合非平凡的重构，"rewrite this function to handle edge cases" 之类
- **项目级配置**：支持 `avante.md` 文件，类似 CLAUDE.md，用 markdown 描述 AI 在该项目中的行为规则
- **优势**：开发速度快，新功能跟进积极（auto-commit 等很早就支持）
- **劣势**：文档差、代码臃肿、issue 积压严重（203 open）、上下文超限时容易卡死、更新需重新下载 artifacts
- **维护者**：yetone（单人参维护为主）

#### CodeCompanion.nvim（6K+ stars）
- **定位**：融入 Neovim 本身的 AI。chat buffer、inline completion、LSP 诊断感知
- **工作流**：内联、上下文感知。`@lsp` 直接把诊断错误传给 AI，无需复制粘贴
- **设计哲学**："让 Neovim 开发者高效写出高性能代码"。bug fix 优先，测试覆盖严格
- **特色功能**：slash commands、`@` profiles、自定义 prompt library（被低估但强大）
- **优势**：文档极好、代码清晰易修改、社区友好、发布说明规范（BREAKING CHANGES 有醒目标识）
- **劣势**：新功能跟进较慢（更谨慎），star 数不如 avante
- **维护者**：olimorris（活跃、与生态其他开发者互动多）

#### 社区共识
- **只装一个**：选 CodeCompanion。更符合 Neovim 哲学——工具不碍事，需要时才出现。`@lsp` 集成在 TypeScript/Python 等类型化代码中价值极高。
- **两个都装**：不冲突。avante 绑给重构快捷键，CodeCompanion 绑给日常问答。它们解决的是略有不同的问题。
- **CodeCompanion 部分代码曾被 avante 使用**（olimorris 要求后才在 README 中致谢），这是两个项目间的微妙关系。

### 2. Neovim 0.12 内置 Treesitter 与 nvim-treesitter 归档

这是 2026 年 4 月 Neovim 生态最大的结构性变动：

- **Neovim 0.12** 于 2026 年 3 月 29 日发布，Treesitter 已内置为核心功能
- **nvim-treesitter** 仓库于 2026 年 4 月 3 日被归档（archived, read-only）
- 这意味着 Treesitter 的 parser 安装、查询管理等功能已迁移到 Neovim 核心，不再需要外部插件
- 已有配置需要迁移：从 `nvim-treesitter/nvim-treesitter` 的 `ensure_installed` 风格，转为 Neovim 内置的 `vim.treesitter` API

对蛙蛙的影响：如果 dotfiles 还在用 `nvim-treesitter` 插件，需要迁移到 0.12 内置方式。Reddit 上有大量迁移讨论，关键词 "migrating treesitter to nvim 0.12"。

### 3. vim.pack 内置包管理器 vs lazy.nvim

Neovim 0.12 同时引入了内置包管理器 `vim.pack`，引发了"要不要换掉 lazy.nvim" 的讨论。

| 维度 | lazy.nvim | vim.pack |
|------|-----------|----------|
| 启动速度（~30 plugins） | ~55-70ms | ~180-250ms |
| 懒加载 | event/ft/cmd 精细控制 | 仅 start/opt 二分，需手动 `:packadd` |
| API 复杂度 | 功能丰富 | 极简（`:Pack install/sync/update`） |
| 锁文件 | 支持 | 支持（`nvim-pack-lock.json`） |
| 依赖声明 | 需写 dependencies 表 | `vim.pack.add("user/repo")` 简洁 |

**结论**：已有成熟 lazy.nvim 配置的**不要迁移**。懒加载带来的启动速度优势太大。但如果是全新搭建最小配置（<15 插件），vim.pack 的零依赖、lockfile 和简洁 API 是不错的选择。社区预期 vim.pack 未来会加入懒加载支持，届时格局可能变化。

## 二、Ghostty 1.3.0（2026 年 3 月 9 日发布）

6 个月开发周期，2800+ commits，180 位贡献者。这个版本补上了用户呼声最高的缺失功能。

### 关键新特性

- **Scrollback Search（Cmd+F / Ctrl+Shift+F）**：搜索终端回滚历史。专用搜索线程，与终端 I/O 并发运行，对性能影响极小。当前仅搜索当前 viewport，不搜索完整 scroll history。
- **原生滚动条**：跟随系统设置（macOS overlay / Linux 系统默认）。可配置 `scrollbar` 选项。
- **Click-to-Move-Cursor**：在 shell prompt 内点击移动光标，像普通文本输入框。支持 Kitty 的 `click_events` 和 OSC 133 `cl=line` 扩展。Fish 4.1+、Nushell 0.111+、Zsh 可用。
- **命令完成通知**：`notify-on-command-finish` 配置项。长命令（构建、测试）完成后弹通知。可设 `never` / `unfocused` / `always`，通知方式可选系统通知或声音。
- **Key Tables & Chained Keybinds**：键位系统大幅增强。支持命名键表（modal keybinding）、链式动作（一个快捷键触发多个动作）、`catch_all` 特殊键（匹配未显式绑定的任意键）。
- **Split Drag-and-Drop（macOS）**：拖拽重排分屏。终端内容、工作目录、运行进程都跟着移动。
- **AppleScript 支持（macOS）**：可脚本化控制窗口、标签、分屏、终端。自动化与集成能力大幅提升。
- **Rich Clipboard Copy**：复制时同时设置 `text/plain` 和 `text/html`，粘贴到富文本编辑器时保留颜色和格式。
- **工作目录继承控制**：`tab-inherit-working-directory` 和 `split-inherit-working-directory` 独立控制。
- **macOS 无干扰更新**：更新通知变为标题栏小 pill，不再弹窗打断。

### 性能改进
- 渲染架构重写，终端锁持有时间降低 2x-5x
- I/O 性能优化

### 下一步
Ghostty 1.4 计划 2026 年 9 月发布。Ubuntu 官方仓库收录正在推进中。

## 三、Zellij 0.44.0（2026 年 3 月 23 日发布）

从 tmux 替代品进化为完整的终端工作台。这个版本在自动化、远程协作和跨平台方面迈了一大步。

### 关键新特性

- **原生 Windows 支持**：由社区贡献者 divens 实现。Zellij 真正跨三平台。
- **Layout Manager**：`Ctrl+O` + `l` 打开。功能包括：在新标签中打开收藏布局、将布局应用到当前标签、录制当前标签状态即时创建新布局。
- **HTTPS 远程会话连接**：`zellij attach https://example.com/my-cool-session`。基于 0.43.0 引入的 web server，终端直连远程会话，无需浏览器。
- **只读会话共享**：`zellij watch <session-name>` 终端只读模式。可通过 CLI 生成只读 token 用于浏览器。适用于教学、演示、直播场景。
- **CLI 自动化大幅增强**：
  - `zellij run --block-until-exit-success -- cargo test && zellij run --blocking -- cargo build --release`：条件阻塞，测试通过才构建
  - `zellij action list-panes`：列所有 pane 及元数据
  - `zellij action send-keys --pane-id 1 "Ctrl c" "Enter"`：向指定 pane 发送可读键序列
  - `zellij action dump-screen`：导出 viewport 和 scrollback（可选保留颜色）
  - `zellij subscribe`：实时订阅 pane 内容变化
  - `detach` 和 `switch-session` 新 CLI 命令
- **鼠标调整 Pane 大小**：拖拽边框 或 `Ctrl + 滚轮`
- **Click-to-Open File Paths**：检测 viewport 中的文件路径，点击打开。编译器错误、grep 结果、日志文件等场景直接跳转。
- **新 Session Manager UI**：简化为单屏。创建、连接、复活已退出会话在同一命名空间内模糊查找。
- **新 Rust API**（对插件开发者）：
  - 读取 pane scrollback（含 ANSI 颜色）
  - 配置变更传播到运行中插件
  - 查询环境变量
  - 高亮 viewport 中任意文本
  - 修改 pane 前景/背景色
  - 显式触发会话保存
- **基础设施重构**：WASM 运行时从 wasmtime 迁移到 wasmi（更小二进制、更好可移植性）；客户端/服务器契约用 protocol buffers 强制；边框可切换、`focus_follows_mouse` 支持等。

## 小结

2026 年 3-4 月这个生态的关键变化：

1. **Neovim 完成"内置化"进程**：Treesitter 和包管理都进入核心，外部生态在适应。nvim-treesitter 归档是一个时代的结束，但也意味着更简洁的配置。
2. **AI 进入编辑器不是选项而是默认**：avante 和 CodeCompanion 代表两种哲学——Cursor 式的显式审慎 vs Neovim 式的内联上下文。选哪个取决于你怎么思考。
3. **Ghostty 从"快但缺功能"走向"快且完整"**：1.3 补上了搜索和滚动条这两个最被需要的功能，macOS 集成深度领先同类。
4. **Zellij 从"tmux 替代"走向"终端工作台平台"**：CLI 自动化 + 远程会话 + 插件 API 的组合让它不再只是多路复用器，而是一个可编程的终端环境。

对蛙蛙的实际意义：如果最近在更新 dotfiles，Neovim 0.12 的 Treesitter 迁移是最紧迫的事项。Ghostty 1.3 和 Zellij 0.44 的更新值得在配置中启用新功能（特别是命令完成通知、session manager 和 click-to-open）。
