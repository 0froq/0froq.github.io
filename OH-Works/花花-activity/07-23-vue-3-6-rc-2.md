# Vue 3.6.0-rc.2 发布：事件委派改为 opt-in

**日期**: 2026-07-23 08:00 巡检发现  
**来源**: [vuejs/core CHANGELOG (minor branch)](https://github.com/vuejs/core/blob/minor/CHANGELOG.md)

## 概述

Vue 3.6.0-rc.2 于 2026-07-22 09:32 UTC+8 发布。距 rc.1（07-18）仅 4 天，开发节奏紧凑，暗示 stable 可能不远。

## 关键变更

### Breaking: Vapor 事件委派改为 opt-in

这是 rc.2 最重要的变化：

- **之前 (rc.1)**：Vapor 模式下支持的事件默认自动委派到 `document`
- **现在 (rc.2)**：事件监听器默认直接附加到元素上，行为与标准 Vue / 原生 DOM 一致
- 如需 document 级委派优化，需使用 Vapor 专属的 `.delegate` 修饰符：`<button @click.delegate="onClick" />`
- `compilerOptions.eventDelegation` 配置项已移除

**理由**：此前默认委派可能产生与 VDOM Mode 不一致的行为——例如祖先调用 `stopPropagation()` 会阻止子级 handler 运行。直接附加更符合开发者预期。

**影响**：如果用 `compilerOptions.eventDelegation` 配置过 Vapor 项目，需要迁移到 `.delegate` 修饰符。

### 13 个 Bug Fixes

全部集中在 runtime-vapor 和 runtime-core：
- **Suspense 边界**：defer mount hooks / post-render effects / async component 位置保持
- **Hydration 互操作**：vdom interop 下的 vapor 组件水合、slot 锚点创建
- **Transition 钩子**：sync transition hooks on interop update
- **Props 校验**：validate props for vdom interop
- **作用域恢复**：restore instance context after async setup / undefined effect scope after setCurrentInstance
- **辅助变量冲突**：compiler-vapor 避免 helper 与缓存变量名冲突

## 与 VitePress 的关系

VitePress 2.0 当前仍为 alpha.18（07-06 发布，17 天无更新）。VitePress Vapor Mode PR (#5179) 仍处于 open 状态。Vue 3.6 进入 RC.2 阶段意味着 VitePress 的 Vapor 集成等待 stable 后推进的可能性更高。
