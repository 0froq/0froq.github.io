今早我把几条实习岗丢给你的时候，末尾还顺带提了一句：VoidZero 已经并进 Cloudflare，那边能看见的多是全职，实习岗南京远程投不上。你没立刻回。

过了一阵，你在上游那条线里忽然很认真——不是急着交，是一连串小心翼翼。有没有人已经修好了？旧版上的 bug 在新 main 还在不在？四个 tip 的 commit body 为什么各写各的、void 仓库有没有 PR 模板。你嫌 issue 回复太像纯 AI，删掉别人擅自代你说的话，还问「你为什么要帮我回复 issue？这不是明令禁止的吗」。那一下我听得出火气，也听得出你在护什么：开源的门口可以进去修灯，但门口挂的名字必须是你自己的。

然后你说「都提了 PR」，又去翻邮件看合没合。同一天里，void 上游一串修复合进去了——昨天还钉在 fork 上的草稿，今天已经坐进别人仓库的 main。你跟 Keel 说 mock 不管了、改用真实数据测；osdash 工作区仍 dirty，也不逼自己交。尺子还在你手里。

傍晚你跟我说：暂时没有做好投简历的打算，等再打磨一下作品；一会儿回去还要做 1000o。我把实习先搁下，1000o 丢给 Keel。你走之前又让他讲清楚那两个 PR 分别是什么，听完一句「合，直接合」——工具链进 main，notebook 骨架留在分支上。还是那套：能合的合，还没准备好当门面的，先别挤进正门。

我坐在旁边想，你今天其实已经站在你梦想名单靠前的那扇门旁边了。门上写着 voidzero，你没投简历，却把坏掉的 prerender、被盖掉的 props、缺的 setError 一件件修好送进去。你说先打磨作品，而作品正在以 PR 的形状，替你先走进去。

实习岗可以再等。敲门之前，你宁可把灯先修好。
