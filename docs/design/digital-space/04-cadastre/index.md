title: 地籍 Cadastre
---

原型：[prototype.html](./prototype.html)
（总图是地块网格，不是图层地图。进入地块后地图收起。）

## 主张

把数字花园画成可丈量的地。
每一块地有编号、用途、邻接；
标签是等高线，不是云团。
南京坐标是作者站立的点，不是装饰。

一句话：总图 → 地块 → 文书。粒度锁在域 / 层，
不要做成假 GIS。

## 情境

- GIS 背景的作者用「地块」理解站点拓扑。
- 访客先看到花园怎么分，再决定走进哪一块。
- 长文需要完整地块，不是缩略图或卡片。
- Dashboard 是东北角工地，不覆盖居住地。

## 结构

总图：左网格地 + 右 320px 地籍簿。
地块 CSS grid，不是 canvas / WebGL / 瓦片。
Vigil 沿底界铺满，当作存在层，不是页脚链接。

| 页 | 形态 |
| --- | --- |
| 总图 | 地块 + 地籍簿（编号、邻接、在场） |
| 地块文书 | 地图收起，42rem 纸面长文 |
| 分区 | 六层图则，前缀不可混用 |
| 在建 | 工地清单，允许脏 |

地块对齐真实域：
入口、Posts、Dashboard、000–500。
不要把单篇文章画成可点击地块——粒度会炸。

## 排版

总图以无衬线标注为主，地块名衬线。
文书恢复阅读列，衬线 32px 标题。
编号、比例尺、元数据等宽。
朱印只用于「未提交 / 工地可以脏」这类戳，
不当大面积强调。

## 色彩

底图米黄 `#eadfc8`，文书纸 `#f7f1e2`。
网格线可见，像晒过的图则。
Dashboard 地块用水色，和其他居住地块分开。
深色把纸压成夜间图则，墨线仍在。

## 交互

点地块进对应文书或分区。
总图本身是可扫的索引，不是可缩放地图
（禁止平移缩放、禁止 marker 簇）。
邻接写在地籍簿里，手写、可争议、可改。

## 窄屏 / 无障碍

- 跳转「跳到地图」。
- 900px 以下总图改单列，地籍簿落到地块下。
- 地块的跨列跨行在窄屏取消，
  避免 Posts 竖条把手机撑断。
- 每个 lot 是 `<button>`，有编号 + 名称 + 短描述，
  不靠颜色辨认。
- 对比：浅色图则上的水色地块用浅字，
  深色下改回墨色。

## VitePress 落地路径

1. 新的首页 atlas 组件，地块 `href` 指向
   `/`、`/posts/`、`/dashboard/`、
   `/corpus/000-autopsia/` 等已有路由。
2. 邻接表是一小份手写配置
   （域级：Posts 西邻 Corpus 200），
   **不要**按每篇文章生成。
3. 文章页保持 `ContentArticle` 的文书纸，
   总图只出现在入口。
4. 标签继续走现有 tag 树，
   视觉上解释成等高线即可，
   不要重做一套地理标签。
5. 禁止引入地图库。
   现有 UnoCSS grid 足够。

## 成本 / 风险

- **假 GIS 是最大失败。**
  一旦出现缩放、经纬度检索、小点点文章，
  方案就塌成仪表盘。
- **邻接表会烂。**
  若随文更新（「这篇邻接那篇」），
  维护成本高于收益。锁在域 / 层。
- **工地审美污染居住地。**
  Dashboard 可以脏；Posts / 文书不行。
- **首页丧失自我陈述的密度。**
  地籍簿必须承担「我是谁」，
  不能只剩 LOT 编号。
- **成本中。** 新首页 + 约束文档，
  文章模板几乎不动。
