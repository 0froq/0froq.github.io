title: 分屏 Workbench

原型：[prototype.html](./prototype.html)
（默认深色。⌘K / `/` 开命令面板。左树 / 中缓冲 / 右检查器。）

## 主张

站点即工作台。
访客默认不该看见这个界面；
作者日常——改 Markdown、看 frontmatter、盯 board——
应该像在仓库里打开文件。

一句话：树、缓冲、检查器，而不是页面。

## 情境

- 作者在 Neovim / 浏览器之间校对一篇成言。
- 需要同时看见路径、正文、YAML、在场。
- Dashboard 不是「去访问的页面」，
  是 `board.yml` 的投影。
- 无 JS 时中列仍须可读。

## 结构

三列：`220px` 树 + 弹性中列 + `280px` 检查器。
顶栏 36px 菜单，底栏 26px 状态。
首页不是营销 hero，是 untitled 缓冲：
提示打开文件或按 ⌘K。

| 缓冲 | 中列 | 检查器 |
| --- | --- | --- |
| index | 自我陈述短笺 | kind / locale / ghost / doing |
| 成言 | 渲染后的 Markdown | frontmatter、标签、大纲、在场 |
| corpus | 六层目录 | 前缀规则、计数、hashtag 纪律 |
| board.yml | YAML 源 + 说明 | active 任务列表 |

树的节点对齐真实路径：
`posts/620-roadmap/`、`corpus/000-autopsia/`、
`dashboard/board.yml`。

## 排版

中列 16px / 1.75 / 62ch，标题衬线。
树和检查器 11–13px 等宽标签。
强调色只有一处琥珀，当选中与状态，不当渐变。
深色是这个方案的主材料；浅色是备选。

## 色彩

深色底 `#121212`，面板略抬。
浅色是纸色工作台，不是把深色反相成灰白 SaaS。
选中行 `#2a271f`（浅色 `#f0ead8`）。

## 交互

- 点树或顶栏切缓冲；hash 同步。
- ⌘K / Ctrl-K / `/` 打开 `<dialog>` 命令面板。
- Escape 关闭。
- 检查器随缓冲换 dl。
- 主题可切，但本案默认深色。

原型里窄屏用 `data-mobile-pane` 显示树或检查器，
**脚本未写入该属性**。
落地时必须补：否则 <900px 只剩中列，
树和检查器被 `display: none` 且无法唤出。

## 窄屏 / 无障碍

- 跳转「跳到编辑区」。
- 900px 以下改单列；
  树 / 检查器要有明确开关，不能只藏。
- 命令面板 `aria-label`，输入框可聚焦。
- 中列在无 JS 时显示默认缓冲全文
  （VitePress  SSR 已有正文，不要依赖 hash 脚本）。
- 焦点描边用强调色 1px，适应密界面。

## VitePress 落地路径

当作**写作模式开关**，不是全站默认：

1. 例如 `?mode=work` 或 header 切换，
   仅作者或本机开启。
2. 左树由现有路由生成，
   不要维护第二份 sitemap。
3. 中列复用 `ContentArticle` /
   corpus / dashboard 现有渲染。
4. 右栏接 `AnnotationList`、frontmatter、
   `GhostPresenceRail` 的摘要，
   而不是再做一套卡片。
5. 命令面板可后做；
   中列可读是硬门槛。
6. 不要把 `board.yml` 做成可写 CMS。
   检查器是只读投影，写入仍走文件。

## 成本 / 风险

- **成本高，且像 admin。**
  与「纸面花园」身份冲突，故不能当访客默认。
- **无 JS 失败模式：**
  三列若全靠客户端拼，SSR 会空。
  中列必须是真实页面。
- **窄屏脚本缺口**已在原型里暴露，落地必补。
- **⌘K 与浏览器 / 系统快捷键冲突**，
  要可关。
- **深色默认**会否定现站浅色纸纹。
  若只想要检查器，把三列借到页边方案更便宜。
