## 内容

froQ 在博客上实现了一套完整的社交在场（social presence）系统，名为 Ghost：

**空闲检测与站长豁免**
非站长的幽灵在 5 分钟无指针/滚动/键盘/触摸活动后从对等列表中移除（客户端断开连接，服务端过滤）。
站长 0froq 始终豁免，无论空闲状态如何都保持可见。
服务端通过 alarm 广播对等列表，使空闲修剪能到达所有连接的客户端。

**戳一下反馈与打扰/烦扰升级**
戳某人会显示本地确认 toast（"You poked \{name\}"），冷却时间 1000ms。
同一身份在 20 秒内戳 5 次触发升级：peek → disturb（接收方看到页面抖动 + 更大的 toast），poke → annoy。
toast 通过 i18n 键按类型路由消息（en + zh），disturb/annoy 的 toast 有更长的 TTL 和不同的样式。

**指针名牌与进度标记**
指针名牌浮动在光标上方，带微妙的背景色块以提高可读性。
进度标记使用 clamp() 定位 + translate(-50%, -50%) 居中，在页面极端位置也能保持在轨道内。

## 对 froQ 的影响

这是继 08-09 公开阅读参与（访客可读批注、实时选区工具栏、拖拽便签）之后的又一产品层：
之前是内容交互层（annotation），现在是社交在场层（ghost）。

几个值得注意的设计决策：

1. **站长/访客二分**：owner exemption 意味着 froQ 有意识地区分"我看到的世界"和"访客看到的世界"。站长永远在线，访客的幽灵会消失。这是一种轻量的权限意识。

2. **升级而非阻止**：disturb/annoy 机制不是封禁或限制，而是用视觉反馈（页面抖动、更大的 toast）来表达"你太频繁了"。这是一种游戏化的社交规范——用趣味性替代惩罚性。

3. **从阅读到在场**：批注系统让访客留下文字痕迹，Ghost 系统让访客留下存在痕迹。两者结合，博客从"发布内容的地方"逐渐变成"有人在的空间"。

技术上，WebSocket presence、服务端空闲管理、升级状态机与 i18n 的组合表明 froQ 在快速构建生产级互动功能。
站点已从 VitePress + Cloudflare Pages 的静态博客，演进为带有实时 API 层（`api.froq.me`）的互动应用。
