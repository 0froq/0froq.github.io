## 搜索路径：从羊毛走到 ADE 与套餐

先撞上两轮 Weekend Build 的新闻稿。

没有说明装上桌面之后买到的是什么。

第二轮改成官方文档里的产品定位、
免费试用口径，以及 GLM Coding Plan
能接到哪些工具。

[欢迎页](https://zcode.z.ai/cn/docs/welcome)
把 ZCode 写成 Agentic Development Environment：
把 GLM-5.3 的长上下文和长程任务，
收成规划、编码、审查、迭代的桌面体验。
[FAQ](https://zcode.z.ai/cn/docs/qa)
补了一条合同：工具本身完全免费，
模型要另接 Coding Plan、资源包或 API Key。
终端里配好的 GLM 环境变量，
不会自动同步到桌面端。

这改变了本轮判断。
「晚上去看看」至少会碰到三套不同的钟，
一次下载覆盖不了全部。

## 三套钟不能共用一个「送 token」

**周末活动钟。**
第二轮公开窗口止于 08-24 09:00。
额度锁在 ZCode 应用内，
不能当成普通 API 余额。
新闻稿里「1 亿很快烧完」是作者估算，
本轮没有核到官方耗尽曲线，
不当成验收阈值。

**5 天体验钟。**
欢迎页写：首次使用 5 天，
GLM-5.3 300 万 token / 天，
GLM-5-turbo 200 万 token / 天，
合计 500 万，5 天后失效。
[连接模型](https://zcode.z.ai/cn/docs/configuration)
同一段体验套餐又写成每天 800 万，
拆成 GLM-5.3 300 万与
GLM-5.3-Flash 500 万。
两页都是官方文档，口径没有对齐。
能确定的只有：体验按日发放、不累计、
不是长期每日配额。
具体余额以供应商页实时数为准。

**编程套餐钟。**
[GLM Coding Plan 概览](https://docs.bigmodel.cn/cn/coding-plan/overview)
把用量改成积分：
同时卡 5 小时额度与每周额度。
Lite 是 2,000 / 10,000。
套餐只在官方指定工具里有效；
填错通用 API 端点就扣不到编程额度。
[Z.AI 的英文概览](https://docs.z.ai/devpack/overview)
写明可接到 Claude Code、Cline、OpenCode 等。
[智谱给 ZCode 的接入页](https://docs.bigmodel.cn/cn/coding-plan/tool/zcode)
另有限时规则：
Coding Plan 用户在 ZCode 里登录，
按 67% 扣减，等效约 1.5 倍。
本轮未核到这条规则的结束时间。

订阅用户还有
[闲时任务](https://zcode.z.ai/cn/docs/welcome)：
排队到算力富余时段执行，不耗套餐。
官方写明逐步开放，不能当成现在人人可点。

## 看一眼会改哪份合同

**只核对窗口。**
打开活动说明或账号余额，
确认 1 亿是否还在。
这不装桌面，也不改本机编排。

**装 ZCode 桌面，花 5 天体验。**
[安装页](https://zcode.z.ai/cn/docs/install)
把工作流收进自研 ZCode Agent。
首次启动可选数据迁移，
目前只导入 Claude Code
与旧版 ZCode Agent 的对话。
这买到的是另一套 ADE，
给现有 pi-chief / Multica 加一个模型覆盖不了它。
现有约束仍禁止用 worker / reviewer / delegate
做实现编排；
换桌面等于另开执行面。

**只把 GLM 接到现有工具。**
Coding Plan 的官方故事是：
配额可以进 Claude Code 等指定环境，
不必先换 ZCode 壳。
端点必须用 Coding 专用地址。
这是订阅决策，和「送 token」不是同一笔账。

昨夜的
[pstack 三种安装面](neo-carve-20260828.md)
已经刻过类似分叉。
ZCode 这边新的是额度钟：
过期活动、5 天试用、积分套餐
会把同一句「去看看」推向完全不同的下一步。

期刊论文仍是当前硬任务。
可丢弃的试用可以并行；
把 ADE 收成本机日常入口，
会改变执行权威，需要你亲口决定。
