第一轮若按 Unix 习惯去搜 pstack，
会先撞上进程栈追踪工具。
把两个词放在一起后，路径才转到

[README](https://github.com/cursor/plugins/blob/main/pstack/README.md)

不想用更多 slop 换吞吐量；
想先走深，再并行。

[poteto-mode 的 SKILL.md](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/SKILL.md)
把它写成默认入口。
多步任务先开 todolist，第一项是读完整原则索引；
再按任务匹配 22 份 playbook，
需要时才加载 how、architect、swarm、unslop 等叶子。
它带 `mode: true` 与 `disable-model-invocation: true`：
这是人触发的粘性工作方式，
不是模型随手套上的口头禅。

## 搜索路径：从栈追踪走到运行时原语

第一轮缺口是：
知道它是技能树，仍不知道「玩一下」要装什么。
第二轮把关键词改成 Cursor 原语、
Claude 移植里故意不搬的部分，
以及 Never Block on the Human。

[Agent Skills 标准](https://agentskills.io/)
把技能定义成带 `SKILL.md` 的可移植文件夹，
用名称与描述做发现，匹配后再读全文。
pstack 的叶子大体遵循这个形状。
插件整体还依赖另一层：
Cursor 的 Task / AskQuestion、`/loop`、
Graphite 栈、云端 agent、sticky mode 的 frontmatter。

[pstack-claude 的移植说明](https://github.com/michael-denyer/pstack-claude)
把这些原语逐项替换成 Claude Code 的
Agent、AskUserQuestion、loop。
它明确不搬 sticky mode、Benny 自动化包和 Cursor 教程。
这改变了本轮判断：
同一句「玩 pstack」，至少有三种安装面，
一次 `npx skills add` 覆盖不了全部。

## 三种安装面分别买下什么

**官方 Cursor 插件。**
`/add-plugin pstack`，再 `/setup-pstack` 选模型，
之后用 `/poteto-mode` 做事。
这买到完整 playbook、子代理路由，
以及作者说的 fearless parallelism。
前提是工作发生在 Cursor 里。

**可移植原则。**
Laziness Protocol、Subtract Before You Add、
Prove It Works、Guard the Context Window，
都可以当独立阅读材料。
[Never Block on the Human](https://github.com/cursor/plugins/blob/main/pstack/skills/principle-never-block-on-the-human/SKILL.md)
把可逆工作写成 proceed-then-present，
把 force-push、删除生产数据、对外发信留在确认闸门。
原则要求引用必须对应一次真实选择；
只报技能名不算遵守。

**另一套运行时的整树移植。**
Claude Code / Codex 移植证明技能正文能改写，
也证明粘性模式、事件自动化和 UI 教程并不跟着走。
把它装进当前的 pi-chief / Multica 路径，
等于改助理的编排合同，不是试玩。

本地已有 ponytail（最小可用的编码阶梯）
与 caveman（压缩表达）。
pstack 的 laziness 与前者同向。
[unslop](https://github.com/cursor/plugins/blob/main/pstack/skills/unslop/SKILL.md)
要求第一稿就去掉 AI 腔，
短句仍须保住判断、取舍和未决问题。
单纯少写 token 量不到这条尺子。

## 真正新的合同是可验证的并行

README 把并行写成：
先让单个 agent 写得可验证，再放心开多个。
官方用法也反复落到同一组约束：
并行写者不要共享一个工作目录；
arena 比较同一题的多种答案，
swarm 才切分覆盖面；
绿灯构建不能代替真实产物。

这几条不依赖 Cursor。
它们改变的是「玩一下」的最小实验：

1. 在 Cursor 里对一个可丢弃的小任务跑 `/poteto-mode`，
   看 playbook 有没有改变步骤顺序。
2. 抽一条原则做对照，
   例如 Never Block 是否适用于当前「必须先问」的边界。
3. 不要把 swarm / orchestrate 直接接到本机生产编排。
   现有约束已经禁止用 worker / reviewer / delegate
   做实现编排。
