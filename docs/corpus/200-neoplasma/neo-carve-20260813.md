## 官方警告把环境写进了故障条件

Tracker 凌晨发现，foostan 已在
[crkbd 官方 README](https://github.com/foostan/crkbd)
加入一段针对 Corne v4.* 的警告。
目前有人报告电磁干扰会让左侧、右侧或两侧停止工作，
常见干扰源是手机。官方给出的处理动作很短，
重新连接 USB，把可能产生干扰的设备移到键盘三十厘米以外，
随后继续观察。

这条信息对使用者有直接价值。
分体键盘的一侧突然失灵，人很容易先怀疑半间连接线、
USB 线、固件或焊点。官方警告增加了一个更便宜的检查项。
它不需要拆机，也不需要立即刷固件，
只需改变手机与键盘的相对位置，重连一次，再看故障会不会回来。

README 把这项问题写成目前仍有报告的 bug，
并链接到尚未关闭的
[issue 265](https://github.com/foostan/crkbd/issues/265)。
这表示三十厘米是一条现阶段的观察建议，
还不能当成经过完整测试的安全界线。
桌面上的手机型号、发射状态、键盘版本和线材布置都会变化，
一次恢复也只能证明这项干预与恢复同时发生。
若手机移开后连续多次都不再复现，证据才会逐渐变强。

## 同一种症状背后有几条不同故障路径

分体键盘比普通键盘多了一段半间通信。
[QMK 的分体键盘文档](https://docs.qmk.fm/features/split_keyboard)
说明，这类设备通常有两个控制器，
一侧连接主机，另一侧通过串行或 I2C 与它通信。
因此，一侧不出字可能发生在供电、半间数据传输或主机 USB 连接上。
症状相似，故障位置可能相隔很远。

[splitkb 的单侧故障指南](https://docs.splitkb.com/troubleshooting/one-half)
给出了一种朴素的分流方式。
另一侧完全不亮时，先看它是否得到供电。
另一侧亮着却没有按键输出时，数据传输更可疑。
之后再检查半间线是否插紧、导通是否正常，
两侧固件是否匹配。

Corne v4 的 EMI 警告应当放在这套排查顺序前部。
它针对的是间歇故障，尤其适合处理
「已经正常工作一段时间，随后突然断开」的情况。
issue 265 的报告者有两把来自不同卖家的 rev 4.1，
在一台 Linux PC 和两台 Dell Linux 笔记本上出现相似问题。
设备有时能运行数小时，之后又会每隔几秒失败。
报告里的内核日志反复出现 USB reset、descriptor read error
和 error -71，说明主机看到的是 USB 通信反复失效，
却没有单靠这些日志确认干扰从哪里进入。

这份 issue 提供了复现范围，也留下了边界。
两把键盘与三台主机降低了单台电脑偶发故障的解释力，
仍不足以给所有 Corne v4 判定相同根因。
仓库给该 issue 标了 PCB 修复请求，问题也保持开放。
当前最可靠的行动仍是按官方建议先做距离测试，
随后记录自己的复现条件。

## 排障时先保留现场，再改一个变量

这种故障最怕连续做很多修复。
换 USB 口、换线、刷固件、移动手机若在同一轮完成，
键盘恢复以后仍然不知道哪一步有效。
下一次再断，只能从头猜。

更合适的第一次处理可以很小。
故障出现时先记下哪一侧停止工作，
两侧灯光是否还亮，手机放在哪里，
键盘已经连续工作多久。先不要动半间连接线。
把手机或其他正在发射的设备移到三十厘米以外，
再按官方说明重连 USB，继续原来的工作。

如果故障消失，下一次复现时重复同一动作。
两三次结果方向一致以后，
可以把桌面摆位当作一项临时控制措施。
若手机已经远离，故障仍旧回来，
再沿供电、数据传输和固件一致性继续检查。
这样每一步都会留下可比较的前后条件。

处理半间线时还要保留一条安全边界。
QMK 与 splitkb 的文档都提醒，
部分以 TRS 或 TRRS 传递电源的分体键盘不能带电插拔半间线。
应先断开 USB 供电，接好半间线，再恢复 USB。
具体连接器与接线仍以手中版本的官方资料为准。
这条通用警告不能替代 Corne v4 的版本说明，
却能避免排障动作本身制造新的损坏。

## 一份能回到设计者手里的复现记录

官方 README 正在征集新的信息。
一条有用的报告需要让别人知道怎样再次碰到问题。
型号应写到 v4 或 v4.1，左右哪一侧失效也要分清。
主机与操作系统、USB 连接方式、固件来源、
半间线类型和手机距离会影响解释，值得一并记录。

时间信息同样重要。
键盘是接通后立刻失败，还是工作几小时以后失败，
两种情况指向的排查方向不同。
若移动手机并重连 USB 后恢复，
应写下移动前后的约略距离与恢复持续时间。
有条件时附上系统日志，
但不要把 USB 错误码直接写成已经确认的 EMI 证据。
日志证明主机在哪一步看见失败，
距离测试才开始触及环境条件。

这件事也修正了人体工学键盘试用的评价方式。
[7 月 23 日的 Corne 迁移实验](./neo-carve-20260723.md)
主要观察腕部不适、布局适应和真实任务表现。
硬件稳定性原本只是一个隐含前提。
现在它应成为独立观察项。
若按键中断会迫使人频繁重连，
打字速度与疲劳记录都会混入设备故障造成的扰动。
先把故障时间与桌面环境记开，
才能继续判断布局本身是否适合长期使用。
