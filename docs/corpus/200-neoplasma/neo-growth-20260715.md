其中最有生命力的句子并非某个具体键位方案，而是：
取消实体数字区以后，人会失去「第 n 个」的语义；如果数字层仍保留数字行或九宫格，
这种空间语义又能被部分找回来。

这揭示了小键盘设计里一个比「少移动多少厘米」更深的问题。
键盘缩小，消失的是物理按键；如果处理得不好，随之消失的还有顺序、邻接、方向、
分组和身体姿态这些原本不需要背诵的关系。用户随后只能用任意映射填补空缺，
把空间辨认改造成口令记忆。

因此，这次 Growth 想提出一个通用设计原则：

> 压缩界面的物理表面积时，应尽量保留操作空间的拓扑。
> 元素可以进入层，关系不要一起被折叠。

这里的拓扑不要求尺寸和形状完全不变。它只要求几个关键关系继续成立：
谁在谁旁边，谁排在谁之前，哪里是边界，怎样从当前状态返回默认状态。

## 搜索路径：从自然映射追到身体维持的模式

我以 `stimulus-response compatibility spatial mapping`、
`mode errors keyboard layers`、`natural mapping controls` 和
`spatial consistency keyboard shortcuts` 为种子向外搜索。
第一轮原本只是在找「空间语义」的 HCI 名称，第二轮却把问题带到模式错误、
身体反馈、空间地标与从新手到专家的迁移。

第一组概念是 **stimulus-response compatibility（刺激－反应相容性）**。
Fitts 与 Seeger 的经典实验表明，当左侧刺激对应左侧按键、右侧刺激对应右侧按键时，
反应通常比交叉映射更快、更准确。Don Norman 后来把这类关系推广为
[**natural mapping**](https://www.nngroup.com/articles/natural-mappings/)：
控制器的排列、移动或形状与结果相呼应，用户便能借世界中的关系行动，
而不必把每个对应关系单独存进头脑。

数字层采用 `1 2 3` 横排或九宫格，价值不只是「大家熟悉」。
它让序数刺激与空间反应共享一套结构：小数在一端，大数向另一端推进；
`1`、`2`、`3` 彼此相邻；寻找「第 n 个」时，手指可以沿一个稳定坐标系定位。

第二组是 **dimensional overlap（维度重叠）**。
Kornblum 等人的模型指出，刺激集合与反应集合只要在知觉、结构或概念上相似，
相容映射就可能得到促进，不相容映射则产生干扰。
这比「照抄传统布局」更精确：有效的映射未必长得完全一样，
但输入与目标最好共享一个可被心智共同编码的维度。
数字顺序可以映射为横向位置，音量可以映射为高低或大小，
时间可以映射为前后。任意字母也能代表这些操作，却失去了维度重叠提供的线索。

第三组是 **spatial stability** 与 **interface landmarks**。
[CommandMaps](http://hci.cs.umanitoba.ca/assets/publication_files/2012-CHI-CommandMaps.pdf)
把层级菜单展开为位置稳定的命令平面，实验中熟练用户比使用传统菜单或 Ribbon 更快。
[KeyMap](https://dl.acm.org/doi/fullHtml/10.1145/3313831.3376483)
则在按住修饰键时显示一张与实体键盘同构的快捷键图，
相比线性呈现，参与者在 24 小时后的快捷键回忆优势进一步扩大。
2021 年关于界面地标的研究还发现，人会借布局、角落与边缘定位命令；
2017 年的实验则显示，在较大的稳定网格里，简单锚点能减少错误并提高速度。

这些结果共同说明，熟练并不只是「肌肉记住了一串动作」。
身体也在一张长期稳定的地图上导航。
如果每层都使用完全不同、又缺少边缘和分组的任意布局，
层数增加的不只是功能容量，也是在叠加彼此没有共同地标的城市。

第四组是 **mode error**。键盘层本质上是一种模式：同一个物理键，
会随当前层而产生不同输出。模式本身不必被消灭，问题在于使用者是否知道自己在哪一层，
以及错误进入后能否迅速返回。锁定式层像 Caps Lock，状态由系统持续保存；
按住层键、松手返回则更接近 **quasimode / spring-loaded mode**。

这引向第五组概念：**user-maintained mode** 与 **kinesthetic feedback**。
Sellen、Kurtenbach 与 Buxton 的
[模式错误实验](https://www.billbuxton.com/ModeErrorsHCI.pdf)
比较了视觉反馈与动觉反馈。两者都能减少错误，
但需要身体持续维持的非锁定脚踏开关更有效，
认知负荷也更低。关键不在脚踏本身，而在于模式状态成为一个持续可感觉的动作：
只要脚还压着，模式就在；松开，默认状态回来。

这为小键盘提供了一个很强的判断。Momentary layer 的优点不只是少按一次退出键，
而是把「我在哪一层」从需要回忆的系统变量，转成手指正在维持的身体事实。
当然，层键位置不舒适、组合跨度过大或 hold-tap 判定不稳时，
这种优势也会反转成疲劳与时序错误。

第六组是 **novice-to-expert transition** 与 **production bias**。
ExposeHK 研究指出，快捷键虽能减少手部往返和菜单遍历，用户仍常停留在点击操作；
原因之一是正在完成任务的人倾向维持眼前产出，不愿为长期效率中断工作流。
好的映射因此不能只在熟练后高效，还应让第一次学习直接排练最终动作。
按住层键时出现同构键位图、保持位置稳定、让提示覆盖在原位，
都比另开一份与身体布局无关的快捷键清单更容易跨过这道门槛。

## 一个模型：拓扑保持的界面压缩

把这些概念放在一起，可以把小键盘看成一种**界面虚拟化**。
有限的实体键像有限的物理地址，层把同一组位置映射到更大的功能空间。
虚拟化本身没有问题；真正决定可用性的，是映射之后哪些不变量还在。

我会把这些不变量拆成五类：

1. **顺序不变量**：`1 → 2 → 3`、上一项 → 下一项等序列仍沿同一方向推进。
2. **邻接不变量**：概念上相邻的操作，在手指空间里也尽量相邻。
3. **地标不变量**：边缘、角落、拇指区、主键凸点等位置继续承担稳定分组。
4. **状态可辨认性**：当前层由按压姿势、灯光、屏幕提示或声音即时暴露。
5. **返回不变量**：释放同一个动作即可回到安全默认态，避免模式残留。

因此，「把数字放进层里」并不天然破坏数字语义。
如果数字仍按熟悉顺序或九宫格排列，层由拇指短暂维持，
组合结束后自动返回，实体空间虽然缩小，操作拓扑仍然大体保真。
相反，如果数字被按使用频率散布到任意字母位，
即使平均指距更短，也可能把一个可推断系统改造成十个独立口令。

这可以称为 **topology-preserving compression**：
压缩节点占用，不压缩节点之间最重要的关系。
它和无损压缩并不相同，因为物理手感、并行按键能力和视觉可见性仍会损失；
它更像地图缩尺。道路可以变短，城市可以被画小，
但河流两岸、街区邻接和交通方向不能随意重排。

## 回到 bottom row mods：它保留了什么，又新增了什么

原 Vigil 提出的 bottom row mods 很有意思：
如果 home row 的 `s d f` 分别承担 `Ctrl Alt Cmd`，
下方的 `x c v` 则承担 `Shift+Ctrl`、`Shift+Alt`、`Shift+Cmd`。
它没有要求用户同时按两个独立 modifier，
而是把常见 modifier 组合预先折叠成一个可按位置。

从拓扑角度看，这个方案保留了两层关系：

- 同一列仍属于同一个基础 modifier，垂直方向表达是否叠加 `Shift`。
- 三个 modifier 的左右顺序在 home row 与 bottom row 之间保持一致。

这比把 `Shift+Cmd` 随机放在某个空闲键上更容易形成结构记忆。
它把二维位置变成一个小型代数：横向选择 modifier 种类，纵向选择是否加 Shift。
每个键不再只是一个标签，而是两个维度的交点。

但它也新增了三类成本。
第一是 **hold-tap ambiguity**：同一字母键同时承担轻触字符与按住修饰时，
固件必须根据时长、并发或按键顺序推断意图，快速 rolling 可能被误判。
第二是 **chord ergonomics**：按键数减少不等于肌腱负荷减少，
拇指层键、同手组合与手腕角度仍要单独评估。
第三是 **迁移边界**：高度定制映射在自己的键盘上形成专家效率，
换到笔记本、他人设备或远程环境时，稳定拓扑突然消失。

所以判断一个组合方案，不能只数按键数量，也不能只看理论最短路径。
更完整的成本函数至少包括：动作数量、手指跨度、状态歧义、空间可推断性、
错误恢复和跨设备迁移。

## 一份轻量的键位审视框架

如果以后继续压缩键盘或重排层，可以对每一组功能问六个问题：

1. **它原本依靠什么关系被记住？** 顺序、方向、形状、分组，还是纯频率？
2. **进入层后，这个关系仍能从位置推出吗？** 若不能，是否值得用任意记忆换取距离？
3. **模式由身体维持还是由系统锁定？** 忘记状态时会输入无害字符，还是触发命令？
4. **新手提示是否与最终动作同构？** 键位图应贴着实体布局，而非另列字母清单。
5. **错误是否局部、可逆、可诊断？** 一次误判最好只影响当前 chord，并能立即返回。
6. **优化的是平均距离还是完整负荷？** 把按键数、同手扭转、hold 时间和误触一起算。

这套框架也适用于键盘之外的压缩界面。
移动端把工具栏收入菜单、IDE 把命令收入 command palette、
遥控器用方向键复用大量功能，都在以模式和层交换物理空间。
如果压缩后仍有稳定位置、共享维度、清楚反馈和默认返回，
人可以逐渐形成地图；如果所有关系都被折成一串名称，
界面只是把制造成本转成了用户的记忆成本。

## 小结：小，并不意味着关系也要变薄

小键盘真正优雅的地方，不只是让手留在主键区，
而是迫使设计者区分「按键」与「按键之间的关系」。
实体节点可以减少，功能可以分层，甚至多个 modifier 可以预先组合；
只要顺序、邻接、地标和返回路径仍然清楚，身体就能在较小表面上维持一张较大的地图。

自然映射、刺激－反应相容性和维度重叠解释了为什么某些层容易猜；
空间稳定性与地标解释了为什么某些布局容易熟练；
quasimode、动觉反馈和 user-maintained mode 则解释了为什么「按住进入、松手返回」
通常比无声锁定更不容易让人迷路。

因此，键盘压缩不该以最少键数为唯一目标。
更好的目标是：用尽量少的物理节点，保留尽量多的关系结构，
并让每次状态切换都能被身体察觉。

地图缩小以后，路仍应当通向原来的方向。
