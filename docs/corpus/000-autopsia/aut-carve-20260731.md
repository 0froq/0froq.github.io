但从结构上看，清场已经出现至少三种不同动作：

1. 整篇删除；
2. 一篇记录内部的选择性删减；
3. 正文保留，访问标签撤除。

三种动作对记忆造成的后果不同。
整篇删除改变「还保存什么」；
段落删减改变「一件事由哪些部分构成」；
标签撤除则改变「未来会沿哪种身份找到它」。

这次 Carve 追问的因此是一道更窄的问题：

> 当正文仍在，只是旧身份的索引被撤掉，
> 系统是在整理分类、降低召回，还是重新解释过去？
> 怎样让这种柔性的遗忘既不继续支配现在，
> 也不偷偷伪装成从未存在？

## 搜索路径：从 archival description 走到 metadata extinction

第一轮使用 `archival redescription`、
`metadata removal provenance`、`de-indexing visibility`
与 `personal archives identity` 为种子。

这一轮先带回 **archival description（档案描述）**
与 **access point（访问点）**。

Getty 对 metadata 的概括很适合这里：
信息对象同时拥有 content、context 与 structure；
metadata 不只说对象「是什么」，
还记录它由谁、为何、如何产生，后来怎样被管理和使用。
（[Introduction to Metadata](https://www.getty.edu/publications/intrometadata/setting-the-stage)）

DACS 更直接指出，档案描述会影响用户怎样访问和理解记录；
描述是一项持续、迭代且带有价值判断的实践，
档案管理者采取的动作本身也应被记录并可发现。
（[DACS Statement of Principles](https://saa-ts-dacs.github.io/dacs/04_statement_of_principles.html)）

这让项目里的 scope 标签不再只是装饰。
`scripts/generate-tags.mjs` 会读取正文 hashtag，
把 `scope/work/research/warmingHiatus`
展开为各级标签并生成标签路径；
运行时的 `getTags()` 也做同样的层级展开。
所以删掉这条标签，会实际改变站点的导航面与聚类结果。
文件仍能按标题或全文搜索找到，
却不再从「科研 / warmingHiatus」这条路被召回。

第一轮同时带回 **de-indexing（去索引化）**。
一篇关于搜索系统去索引的技术综述区分了删除源内容与降低检索可见性：
去索引不抹掉原页面，
它让页面不再通过原搜索入口出现，
也会削弱对象之间原有的语义关联。
（[Vilella & Ruffo, 2025](https://arxiv.org/html/2501.03989v1)）

这个类比有边界。
Corpus 是个人知识系统，
不是公共搜索引擎，也不在处理同一套法律权利。
但它揭示了一种技术事实：
**存在与可见是两条独立轴。**
只改变索引，就足以改变一段过去在日常使用中的重量。

第一轮留下的缺口是：
如果描述本来就应该随理解更新，
为什么还要保留旧标签或旧分类的痕迹？
难道每次改名都要附一部历史？

第二轮于是转向 `records continuum metadata mutation`、
`deaccession event record`、`archival description revision history`
与 `metadata extinction`。

这轮带回三个补充概念：
**records continuum（记录连续体）**、
**metadata mutation / extinction（元数据变异与消失）**，
以及 **deaccession event（撤藏事件）**。

记录连续体把描述理解成贯穿记录整个生命期的迭代过程：
记录从创建、捕获、组织到成为可用证据，
身份、证据性、活动与检索方式一直相互作用。
（[SAA Dictionary: records continuum](https://dictionary.archivists.org/entry/records-continuum.html)）

这意味着「created 时的标签」没有天然神圣性。
旧分类可以错误、粗糙、过时，
后来的人有权重新描述。
但 metadata 会继承、变异，也会消失；
当旧访问点被撤除而理由未留下，
未来只能看到新的分类状态，
无法区分「原标签不准确」与
「原标签曾经准确，但现已不再承担当前导航」。

撤藏实践给出了一个很小的回答。
University of Oklahoma 的处理指南要求：
已进入馆藏的材料若被销毁、归还或转移，
要在资源记录中写明撤除部分、原因、日期与处理结果，
并创建独立的 Event Record。
（[Documenting Deaccessions](https://guides.ou.edu/archivalprocessing/deaccessioning)）

个人 Corpus 不需要复制机构档案的审批流程。
有价值的是那项分离：
**材料的最终状态是一层，改变状态的事件是另一层。**
正文可以删除，标签可以撤除，
但一次跨层、跨身份的大规模重新描述，
最好有一条低频记录说明它发生过。

两轮搜索最终带回五个改变判断的概念：

1. archival description / access point；
2. de-indexing；
3. records continuum；
4. metadata mutation / extinction；
5. deaccession event。

它们共同把问题从「留还是删」改写为：
**Corpus 应怎样分别管理内容的存留、入口的可见、
解释框架的有效期，以及改变本身的证据。**

## 标签不是事实栏，它是一条召回路线

scope 标签看起来像对正文主题的客观概括，
实际至少承担三种功能。

### 1. 描述：这篇记录涉及什么

`#scope/work/research/warmingHiatus`
可以陈述一篇日记或方法记录的来源场景。
从历史角度说，
一次出差、STL 分解或实验维护确实发生在科研活动中。

### 2. 导航：以后从哪里能找到它

标签生成器会把层级标签加入站点索引。
当用户进入 `scope/work/research`，
这些条目会一起出现。
标签因此是一条可执行的检索路由，
不是只供阅读的注脚。

### 3. 激活：哪个身份会被再次召回

聚合页不只帮助寻找，
还会把分散记录重新组成一个叙事面。
当「科研」标签下聚集论文、实验、受挫、出差与方法记录时，
系统反复提示：这些事情共同属于一个仍有组织力的身份。

撤除标签会同时影响三层。
它可能修正描述，切断导航，也降低身份激活。
三种后果有时正是目的，
有时却会彼此越界。

例如，[《实验的可靠性长在维护层里》](../200-neoplasma/neo-carve-20260622.md)
从一次盐度实验事故出发，
但正文形成的是 treatment fidelity、realized treatment
与 provenance 等可迁移方法概念。
移除窄的 `warmingHiatus` 标签，
可能是在释放这篇条目：
它不再属于某个退出中的项目，
仍然可以作为一般实验方法被使用。

而 [《260531 志》](../300-putredo/put-20260531.md)
保留实验现场、体力劳动、关系与设备限制，
同时撤去科研 scope，
产生的效果更暧昧。
事情仍然发生过，
但系统不再允许「科研」成为它的主要进入方式。
这可以是主权回收，
也可能让未来难以理解为什么会去东山站、
为什么身体与关系压力以那种方式出现。

我无法仅凭 diff 判断哪种解释更接近 froQ 的意图。
能确认的是：
**去标签不是零语义操作。**
它没有删除字节，
却改变了字节被重新组织成何种过去。

## 一份记录至少有四种状态，不应压成「存在 / 不存在」

昨日的 Current / History / Transition
区分了文件在时间中的职责。
今天可以再加一张更细的状态表。

### A. 存留状态：正文还在吗

```text
present      正文保留
partial      选择性删减
removed      从当前仓库撤除
transferred  权威正文迁往其他位置
```

这回答 Corpus 物理上还持有什么。

### B. 可见状态：从哪些入口能遇见

```text
active-indexed    出现在高频任务、首页或主要标签面
indexed           可由稳定标签、索引或明确链接进入
de-indexed        正文存在，但旧访问点已撤除
latent             只能靠全文搜索、文件名或偶然链接抵达
```

这回答一段过去在日常使用中的召回强度。
`latent` 不等于无价值；
它只是被允许安静下来。

### C. 解释状态：旧框架还成立吗

```text
current       旧描述仍准确且仍适用于现在
historical    描述过去准确，但不再指挥现在
reframed      正文保留，新的解释框架取代旧框架
contested     旧、新解释都不足以独占
```

这回答同一份材料应以什么语言被理解。
角色退出最需要的是 `historical` 与 `reframed`，
因为它们允许「过去成立」和「现在改变」同时为真。

### D. 变更证据：为什么变成这样

```text
implicit      只能从 Git diff 猜测
logged        有一条事件记录说明范围、原因与日期
linked        事件记录还指向迁移位置或替代框架
```

Git 能保存差异，
却不会自动保存改动理由。
commit message 若只写 daily sync，
未来仍要从数千行删除中反推意图。

四条轴分开以后，
系统可以做出比「全部保留」或「全部删除」更细的决定：

- 正文 `present`，入口 `de-indexed`，解释 `historical`；
- 正文 `partial`，入口 `indexed`，解释 `reframed`；
- 正文 `transferred`，入口保留一个 `linked` 路标；
- 涉及隐私或明确主权删除时，正文 `removed`，
  事件记录只保留不暴露内容的最小范围说明。

这种状态空间的意义不在于增加 frontmatter 字段。
它只是防止不同操作被一句「清理掉科研内容」压平。

## 柔性遗忘的风险：旧身份退场以后，因果也可能失去索引

去索引化比删除温和，
因为正文仍在；
它也可能更难察觉，
因为文件看起来完好。

### 风险一：保留了事件，却失去了事件为何发生

如果出差日记仍在，科研标签与科研段落全部消失，
未来读者会看到开车、实验桶、鱼、导师与疲惫，
却可能无法从站点导航恢复它们属于哪段工作结构。

正文中的自然语言仍保留部分上下文，
所以这不是彻底失忆。
但索引的因果桥变弱了。
系统可以找到一个故事，
不一定能找到它在生命结构中的位置。

### 风险二：旧标签继续存在，会把已退出角色反复召回

反方向也有真实代价。
若所有旧记录永久挂在高频 `scope/work/research` 下，
标签页就会持续把它们聚合成一个活跃身份面。
每次浏览 Corpus，
旧角色都以完整目录重新出现。

所以「恢复全部旧标签」并非稳妥答案。
身份退出需要降低某些访问点的权重，
让过去从导航主干退到历史支路。

### 风险三：选择性删减会改变一篇日记的内部比例

[《260527 志》](../300-putredo/put-20260527.md)
原本同时记录代理协作与 STL 分解；
删去后者以后，
标题未变，正文更集中，
但这一天「系统搭建与科研重启并行」的结构消失了。

这可能是准确的重编：
日记终于只保留真正想记住的主线。
也可能是后来身份对早期一天进行回溯性剪辑。
两种都属于 froQ 的编辑主权。
Carve 只提醒：
**剪辑形成的新比例也是一种新的叙事，
它不应被误认为当天原本只有这些。**

## 一个最小协议：让过去退到支路，不必继续占据主路

当前不需要给每篇旧记录新增四个状态字段，
也不应恢复 froQ 正在删除的内容。
更小的做法是一份单点的
**description transition event（描述迁移事件）**。

它可以作为昨日 transition note 的一个小节，
只记录这次跨层清场的描述变化：

```text
变更日期：
影响范围：哪些目录、标签与入口
操作类型：removed / partial / de-indexed / transferred
旧访问框架：例如 scope/work/research/warmingHiatus
新访问框架：保留的新 scope，或明确为 latent
目的：停止当前激活、迁移权威正文、删隐私、去重复等
保留边界：哪些历史与通用方法仍在
恢复路径：Git、Quarto 或其他 canonical home
复查条件：什么未来信号会要求重建入口
```

这份记录不必列出每个被删段落，
Git 已经承担字节级历史。
它只补 Git 最难自动提供的三件事：
范围、理由、时间职责。

最小验证也不需要新 dashboard。
清场完成后，用三组自然查询做一次对照：

1. 从 `scope/work/research` 标签页进入，
   是否还会把退出中的项目误呈现为当前主线；
2. 用「东山站」「实验维护」「STL」等事件词全文搜索，
   是否仍能恢复必要的历史因果；
3. 用「treatment fidelity」「realized treatment」等通用方法词搜索，
   保留下来的方法条目是否脱离旧项目后仍可被找到。

三组查询分别测当前激活、历史解释与知识迁移。
完成标准不是科研相关词全部归零，
而是三项同时成立：

- 当前入口不再发出已经失效的行动命令；
- 保留记录仍足以解释它们为何发生；
- 从项目中长出的通用方法不被一起埋掉。

如果第一项失败，说明旧索引仍在后台运行；
如果第二项失败，说明柔性遗忘切断了因果；
如果第三项失败，说明项目退出误伤了已内化的能力。

## 小结：记忆的主权，也包括决定它从哪扇门回来

archival description 说明描述会塑造访问与理解；
de-indexing 把源内容的存在与检索可见性分开；
records continuum 允许描述随记录生命期不断重写；
metadata mutation / extinction 提醒，旧入口的消失本身也会失去踪迹；
deaccession event 则把材料状态与改变状态的事件分开保存。

它们共同支持一个 Corpus 判断：

> 遗忘不只有删除。
> 撤掉一个标签、剪去一个段落、让一篇旧文退出高频聚合面，
> 都是在重新分配过去被召回的权利。

这份权利值得使用。
人不必永远被旧分类找到，
也不必让每个曾经重要的角色持续占据首页、任务与标签主干。
一个知识系统若只会保存，
会让过去不断取得现在的发言权。

但柔性的遗忘也应留下自己的轮廓。
正文还在时，索引撤除会安静地改变关系；
段落仍顺畅时，删减会安静地改变比例；
标签页变空时，一个身份会像从未聚集过那样散开。

好的清场不要求旧身份永远亮着。
它只需要在灯熄灭以后，
留下一张很小的线路图：
这扇门曾经通向哪里，
为什么如今不再从这里进入，
还有哪些东西被带到了别的房间。

过去可以退到支路。
它不再指挥现在，
却仍允许未来在真正需要时，
知道该沿哪一条较暗、但诚实的路回来。
