- [board](../../dashboard/board.yml) 删除「推进论文分析」与
  「部分迁移至 Quarto Site」两项 active 任务；
- [年度愿景](../../dashboard/visions/year-2026.yml)
  删除中英文的「发表一篇论文」；
- [hard context](../../dashboard/advisor/hard.md)
  删除湖泊增温研究项目、论文产出目标与科研工作周描述；
- `docs/corpus/300-putredo/` 中二十一篇旧日记与科研反思待删除；
- dashboard 的日计划、周计划与 advisor 记录大量待删除；
- `OH-Works/花花-activity/` 中一批科研巡逻笔记也待删除。

`git diff --stat` 在本轮显示：
120 个文件发生变化，约 10,970 行删除、96 行新增。
这些数字只描述当前工作树，
不证明它们已经成为 froQ 的最终决定；
Rune Git Sync 尚未执行，Carve 也不会替它提交。

前日的
[《删掉一整类条目，是在给 Corpus 立一块界碑》](./aut-carve-20260728.md)
把论文笔记迁移解释为 Corpus 与 Quarto Site 之间的主权划界。
今天的信号更深一层：
退场的不只是研究材料所在的位置，
还有 dashboard 用来回答「现在要做什么」、
vision 用来回答「今年要成为什么」、
hard context 用来回答「系统应怎样理解我」的身份线索。

如果这些变化最终保留，
它们构成的已经不只是资料迁移，
而是一次**角色退出在知识系统中的落地**。

这次 Carve 因而追问：

> 当一个人不再愿意让某种角色支配当前系统，
> 应该删掉哪些操作性约束，又该留下什么，
> 才能让未来仍看得懂这次转向？

## 搜索路径：从 role exit 走向「改变中的连续」

第一轮以 `role exit identity transition`、
`possible selves`、`narrative identity self continuity`
与 `digital forgetting personal archives` 为种子。

这一轮首先带回 **role exit（角色退出）**。
Ebaugh 将它概括为：
退出一个曾经处于自我认同中心的角色，
并建立一个会把旧角色纳入考虑的新身份。
一项关于创始 CEO 交接的研究在引用这一框架时，
特别讨论了 **role residual（角色残余）**：
人进入新角色以后，旧角色留下的技能、关系、习惯与社会认同
不会同步归零。
（[DeTienne 与 Cardon 等，2015](https://pmc.ncbi.nlm.nih.gov/articles/PMC4621281/)）

Markus 与 Nurius 的
[Possible Selves](https://cmapspublic2.ihmc.us/rid=1LQJK1Z9J-16LFNTG-39MK/Possible%20Selves%20ARTICLE.pdf)
则把身份的未来维度说得更清楚：
人会形成自己可能成为、希望成为、害怕成为的版本；
这些 possible selves 把自我知识与行动动机接在一起。

第一轮暴露了一个缺口：
角色退出与未来自我都解释了「身份为何变化」，
却没有直接回答知识系统里的文件应该怎样随之变化。
如果全部保留，旧身份会继续占据每天的注意力；
如果全部删除，转变又可能失去因果与历史。

第二轮于是改用 `identity based motivation context cues`、
`role residual ex-role`、`autobiographical reasoning self-continuity`
与 `personal archives appraisal identity`。

这轮带回四个补充概念：
**identity cue（身份线索）**、
**action-readiness（行动准备）**、
**autobiographical reasoning（自传式推理）**，以及
**archival appraisal（档案鉴定）**。

Oyserman 的身份动机模型指出，
身份并非持续以同等强度占据心智；
情境中的线索会让某个身份变得显著，
并一同唤起与它相符的行动和理解方式。
（[Identity-based motivation: Implications for intervention](https://pmc.ncbi.nlm.nih.gov/articles/PMC3079278/)）

这让 dashboard 的作用突然变得具体：
active task、年度愿景与 hard context 都不只是静态描述，
它们每天都在充当 identity cues。
把「发表论文」从这些高频入口移除，
可能会真实降低研究者身份对下一步行动的支配力。
这是一项操作性变化，不能被轻描淡写成整理文件。

但自我连续性研究补上另一半。
Habermas 与 Köber 区分了
「因为没有变化而保持相同」和
「承认发生变化、再通过解释把两端接起来」。
他们报告，自传式推理可以缓冲生平中断对自我连续感的影响；
连续不要求过去与现在完全相似，
而要求人能说明变化怎样发生、它意味着什么。
（[论文摘要](https://pubmed.ncbi.nlm.nih.gov/24827019/)）

个人档案研究又提醒：
私人记录同时保存活动证据与自我呈现，
其价值不能完全照搬机构档案的行政留存逻辑。
对个人档案做鉴定，本身就在决定未来能够看见怎样的一个人。
（[Catherine Hobbs, Personal Archives](https://archivaria.ca/index.php/archivaria/article/download/12817/14027)）

于是问题从「删或不删」改变为：
**哪种记录仍在指挥现在，哪种记录只负责证明过去，
哪种记录负责解释两者为什么不同？**

## 三种时间职责不该塞在同一个文件里

当前系统里的科研记录至少承担三种不同职责。

### 1. 当前契约：今天仍要据此行动什么

board 的 active、vision 的年度目标、hard context 的当前项目，
都属于操作层。
它们会影响 advisor 怎样排任务、
Cast 怎样解释 git 静默、
Carve 怎样判断什么值得继续生长。

如果 froQ 已经决定不让论文成为当前主线，
从这些位置删除科研目标是合理的。
继续保留会制造错误的行动准备：
系统每次醒来，都把过去的承诺重新递到桌面上。

这里的完成标准很明确：
后续 planning、Cast 与 Carve
不再默认用「论文是否推进」衡量一天或一周。
这才是身份迁移的行为证据。

### 2. 历史证据：过去实际发生过什么

旧日记、advisor 日志、论文探索与巡逻笔记承担另一种责任：
它们证明某段工作、判断、疲惫、尝试与转向确实发生过。

历史证据不需要继续出现在 active 视野，
却也不该因为失去当前效用便自动失去存在资格。
角色残余并非故障。
研究训练留下的论证习惯、数据敏感度、写作经验，
可能继续进入开源开发、工具设计与审稿判断；
未来回看转向时，旧记录也能帮助分辨：
离开的是研究对象、制度路径、当前优先级，
还是全部研究能力与价值。

这里需要克制。
我不能仅凭工作树判断这些文件为何被删：
它们可能重复、低质、已迁移、有隐私风险，
也可能只是 froQ 不再希望它们出现在这个仓库。
不同原因对应不同处置，
不能用「保存历史」压过明确的删除主权。

### 3. 转变解释：过去怎样长成今天

系统最容易缺少的是第三种记录。
当前契约被改写，旧材料被删除，
两端各自都清楚，
中间却没有一句可追溯的解释。

没有转变解释，未来只能看到 diff：
曾经有论文目标，后来没有了；
曾经有大量科研日记，后来删掉了。
Git 可以恢复字节，
却不会自动恢复这次选择的意义。

自传式推理在这里提供一个很小的结构：

```text
此前是什么：
什么经验使它不再适合作为当前契约：
退出的是哪一部分：
仍然保留什么能力、关系或价值：
新的 possible self 是什么：
哪些证据留在何处，哪些明确删除：
什么未来信号会触发重新评估：
```

这不是要求为每次整理写告别信。
只有跨越多个系统层、改变长期身份线索的操作，
才值得保留一份 transition note。
当前这批变化恰好满足这个门槛。

## 角色退出的系统风险，不止是「删错文件」

### 风险一：旧身份继续通过残余线索后台运行

即使 board 已删除论文任务，
Tracker 若仍高频追踪湖泊热动态，
Cast 仍用科研更新衡量信号价值，
Corpus index 仍把研究主题置于中心，
系统就会出现身份双写：
显式契约说「已退出」，
自动化入口仍每天重新召回旧角色。

这与前日讨论的 dual-write 相似，
但同步对象从文件变成了身份。
迁移完成不能只看目标文字是否消失，
还要看后续行为是否停止围绕它组织。

### 风险二：为了获得自由，把因果也一起删掉

数字遗忘有真实价值。
Mayer-Schönberger 关于数字时代遗忘的讨论指出，
永久可检索的过去可能反过来限制当下自由；
重新引入遗忘，是恢复个人对信息与现在之关系的控制。
（[书评与论述摘要](https://link.springer.com/article/10.1007/s12394-010-0039-x)）

但有效遗忘不等于让所有时间层承担同一种删除策略。
把旧目标从高频操作面移走，
可以减少它对现在的支配；
保留一份低频、非召回式的转变记录，
则允许过去在需要解释时回来。

前者保护自由，后者保护可理解性。
两者并不冲突。

### 风险三：把一次工作树切片过早解释成人生结论

当前变化尚未提交。
它可能是清理过程中的中间态，
甚至可能稍后部分撤回。
Carve 若立刻宣称「froQ 已退出科研身份」，
就是把观察者推断升级为用户结论。

因此本文只做条件判断：
**若这批跨层删除最终保留，
系统正在执行一次角色退出；
若它只是迁移或暂时清场，
仍需要更准确的目标位置与恢复路径。**

Carve 能确认的是结构信号，
不能替 froQ 命名其人生。

## 一个最小协议：退出现行层，保留变形线

如果这次变化在 Git Sync 前仍然存在，
我建议用一个很小的三层协议验收，
不恢复任何用户主动删除的内容，
也不建立新的复杂仪表盘。

### A. Current：当前系统只保留现在仍生效的身份契约

检查这些高频入口：

- board active；
- annual vision；
- advisor hard context；
- Tracker high-priority interests；
- Cast 对能量与价值的默认解释；
- Corpus 首页与主要索引。

验收问题只有一个：
它们是否一致地描述 froQ 现在愿意据此行动的方向？

### B. History：历史记录按原因处置，不按「旧」统一处置

每类删除至少属于一种理由：

```text
migrated     权威正文已迁往其他系统
superseded   已被更准确的记录取代
duplicate    重复且没有独特证据
sensitive    因隐私或主权明确删除
low-value    缺少未来用途与独特历史价值
role-exit    不再允许它充当当前身份线索
```

这只是鉴定词汇，不要求写入每个文件。
它的作用是阻止「不再当前」被自动等同于「毫无历史价值」。

### C. Transition：只留一份短小的转变说明

一份 transition note 足够。
它可以放在 autopsia，
也可以成为 hard context 的更新日志；
内容只需回答此前、触发、退出、保留、去向与复查条件。

最重要的是位置：
它不应每天出现在 active board，
也不应消失在数百篇旧日记里。
它应该低频可寻、明确标注、不会继续发号施令。

这个协议的完成证据也分三种：

1. **行为差异**：下一轮 planning 不再自动恢复论文主线；
2. **历史可解释**：未来只看 transition note，
   能理解为什么旧记录减少；
3. **边界一致**：Tracker、Cast、dashboard、Corpus 与 Quarto
   不再对科研身份给出互相冲突的当前判断。

## 小结：真正的退出，是改变谁有权指挥现在

role exit 说明，退出中心角色需要重建会考虑旧角色的新身份；
role residual 提醒，旧角色留下的能力与关系不会随文件归零；
possible selves 把未来身份接到行动方向；
identity-based motivation 说明 dashboard、vision 与 context
这些线索怎样使某种身份获得行动权；
autobiographical reasoning 则允许人在承认变化的同时保持可理解的连续。

它们共同支持一个系统级判断：

> 身份迁移的核心，不是彻底消灭旧身份留下的每个字节，
> 而是重新分配时间职责：
> 谁负责指挥现在，谁负责证明过去，
> 谁负责解释两者之间发生了什么。

当「研究者」从 active task、annual vision、hard context
与旧记录中同时退场，
这可以是一种清醒的主权回收。
系统终于不再每天要求人履行一个已经松开的承诺。

但好的清场会留下一条细线。
那条线不把人拽回旧角色，
只在未来回望时告诉他：
这里曾经有一条路；
后来路向改变；
有些工具被带走，有些负担被放下；
走到今天的人没有凭空出现。
