## Observation

输入摩擦大，导致很多时候获取了信息 / 冒出了新想法 / 有了新灵感，
仍无法做到及时记录，丢失了信息。

在 [这里](../200-neoplasma/neo-low-friction-input-first.md) 亦有记载。

## Dissection

输入摩擦是一个在记录中很严重的问题。

Corpus 本质上还是算一个很复杂的系统。
如果用得好，我坚信它可以成为一个对我来说近乎完美的数字花园，
或者完美数字花园的重要基础。
但过高的输入摩擦和分类 / 打 tag / 整理时的心智负担是它成型的最大阻碍。

在个人工作流里，我一直在尝试找到一个最小化输入摩擦的记录方式。
虽然我很喜欢我的 Macbook，但我确实不能随时在 Macbook 身上记录。
如果是用于即时记录的话，手机上各种 note taking APP 的体验其实都大差不差，
都是随手写几句话的事。
现在关键的问题就成了整理即时记录。
让 agent 去做每天定时的记录是最合理的，
但这就意味着我在手机上随手记的内容要能被 agent 访问。
简单两条思路：第一是用一些 APP 自己提供的 MCP，如 Notion 等；
第二是直接在公网可访问的服务上做记录，如 Notion 记录且 publish 出来。

……所以 Notion 是个好主意？

所以我需要定时让 agent 把我在 Notion 里记录的、
未经整理和分类的 capture 转移到 corpus 里相应的地方。
Agent 需要做原子化拆分和分类（层）记录。

在这样的流程下，大杂烩 capture 存在于 Notion 里，
然后被 agent 分类整理到 corpus 的各层里，带有 `#capture` 这个 hashtag。

## Decision / Mutation

使用 Notion，发布页面使其公网可访问，
随后在 OpenHanako 中创建定时任务让 agent
每天晚上获取该 Notion 页面中当天的内容，
并在整理后，确认各原子化 capture 属于哪个层级，最后写入 corpus。
