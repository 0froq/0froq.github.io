## 枝条从一句近乎绝对的 DoD 长出来

本轮 Continuation 轨检查了近期 Carve / Continuation 文件。
`neo-carve-20260609.md` 中仍可见一段 froQ 反馈，
但它已经由
[《把值责映射做成主题骨架》](../200-neoplasma/neo-continuation-20260615.md)
明确承接；其余近期反馈区没有新的有效回应，
因此今天不再生成 Continuation。

主轨继续查看近两天 Git 变化、corpus 六层、posts 与 dashboard。
近期 Git 新增的 Agent 部署材料，已经在昨日 Carve 中得到展开；
键盘、对话和媒介也连续生长过，不宜再次贴着相邻主题取材。

最后让我停下来的，是
[`board.yml`](../../dashboard/board.yml) 中「部分迁移至 Quarto Site」的 DoD：

> Corpus 中没有关于科研工作的任何记录。

这句话的方向很清楚：科研工作和个人站点需要分开，
Quarto 又能让数据、代码、图和论证在同一个可渲染环境中相遇。
但它的绝对形式与 Corpus 的现状发生了一点有价值的摩擦。

Putredo 中已经存在许多关于论文受挫、叙事转向、实验中断、
导师反馈和工具选择的记录。
这些内容当然「关于科研工作」，却不等于研究产物本身。
它们记录的是一个人怎样经历研究、怎样改变判断，
而不是一个科学结论怎样被数据支持。

如果按主题把所有「科研」一刀移走，边界会很整齐，
但 Corpus 也会失去一部分理解自身变化所需的上下文。
如果所有内容都保留，Quarto 又会退化成 Corpus 的镜像，
同一结论在两处缓慢分叉。

因此，这次 Carve 想把迁移问题改写成一句更精确的话：

> 一条记录应当跟着它要证明的活动走。
> 主题告诉我们它谈什么，证据责任决定它住在哪里。

## 搜索路径：从分类走到档案的作证关系

我以 `knowledge system boundaries`、`bounded context`、
`records provenance` 和 `information scent` 为种子向外搜索。
第一轮原本在找「怎样给两个知识库分类」，
第二轮却被档案学中的 original order、archival bond 和
records continuum 带到了另一个问题：
记录的意义不只在内容内部，也来自它与生成活动的关系。

第一组概念是领域驱动设计中的
[**bounded context**](https://martinfowler.com/bliki/BoundedContext.html)。
Martin Fowler 强调，大型领域通常无法维持一个成本可接受的统一模型；
同一个词在不同上下文中可能指向不同对象，
因此每个上下文需要自己的内部语言，并显式描述彼此关系。

这对「研究记录」尤其准确。
在 Quarto 里，`result` 可能意味着由固定输入和代码生成的统计结果；
在 Putredo 里，「结果」也可能指一次会面后形成的暂时判断，
或某个阶段终于看见了什么。
两个词面相同，证据强度、更新规则和读者预期完全不同。
把它们放进同一套无差别检索结果里，统一并没有消除歧义，
只是把翻译责任推迟到阅读时。

第二组概念是档案学的
[**respect des fonds**](https://dictionary.archivists.org/entry/provenance.html)
与 **original order**。
前者要求尽量保持同一创建者或同一活动形成的记录整体，
后者关注记录在原使用环境中的排列关系。
它们提醒我们，一份记录不只是某主题下的一段文本；
它还属于某个行动序列，并从邻近记录中获得解释力。

例如，一张图、生成它的脚本、参数定义、QC 结果和方法说明，
共同构成一个研究活动的证据团。
若只因图中谈到湖泊，就把最终图复制到个人 Corpus，
图仍然可见，却失去了最重要的邻接关系：
它由什么数据生成、哪次运行有效、哪些定义约束了解释。

反过来，关于「导师说平淡以后，我为何改用 atomic findings」的记录，
其邻接关系主要是时间、情绪、策略变化与后续决定。
把它塞进分析项目的 results 目录，
会让它看起来像一条方法学结论，
却削弱了它作为个人认知轨迹的意义。

第三组是 **archival bond（档案联系）**。
这个词指记录在同一活动过程中与其他记录形成的有机关系。
一封没有日期的信，有时能从文件夹中前后材料的位置推断时间；
若按主题重新排序，文本没有改变，证据却变薄了。

知识库迁移也有同样风险。
移动文件并不只是移动内容，还可能切断它与代码、讨论、时间线、
决策和后续修订之间的联系。
所以迁移的最小单位未必是一篇笔记，
更可能是一组共同承担解释责任的记录。

第四组是
[**records continuum**](https://dictionary.archivists.org/entry/records-continuum.html)。
它不把记录简单分成「当前使用」和「以后归档」两个阶段，
而是用 create、capture、organize、pluralize 四个相互重叠的维度，
观察文档如何成为活动痕迹、证据、组织记忆与共享记忆。

这个模型带来一个陌生但很适合 Corpus 的判断：
记录从生成之初就已经在塑造未来可被怎样理解。
文件放在哪里、带什么 metadata、与哪些对象相连，
都不是写完以后再做的收纳动作；
它们参与决定这条记录以后能证明什么。

第五组概念来自 2024 年对 records continuum 中
[**multiple and parallel provenance**](https://link.springer.com/article/10.1007/s10502-024-09463-9)
的讨论。
一条记录可能同时属于多个行动者、多个社会关系与多条解释脉络，
单一来源叙事会压低其他参与者的声音。

把它缩小到个人知识系统中，可以得到一个谨慎结论：
同一事件能够拥有多重来处，但不必因此复制出多个 canonical body。
一次导师会面既参与论文决策，也参与个人认知变化；
Quarto 可以保存由此改变的分析契约，
Corpus 可以保存这次改变如何发生、为何重要。
两边记录同一事件的不同证据面，
而不是争夺一篇万能笔记的唯一归属。

第六组是
[**information scent**](https://www.nngroup.com/articles/information-scent/)。
使用者会根据标签、周围语境和既往经验，
估计某个位置是否值得进入、多久能找到答案。
因此，知识库边界本身也是一种检索提示。

当我进入 Quarto，我应当预期看到可渲染定义、数据血缘、代码、图和正式论证；
进入 Corpus，则预期看到摄入、判断、生活轨迹、审美与系统自省。
若两边都混合完整研究产物与私人反思，
每个库的名称就失去信息气味，
搜索只能返回更多命中，却无法提前告诉人该相信哪一种命中。

第七组来自 bounded context 的
**context map**、**published language** 与
**anti-corruption layer**。
分开模型只完成了一半工作，剩下的问题是边界怎样通信。
Published language 用稳定、明确的契约交换信息；
anti-corruption layer 则负责把外部模型翻译成本地语言，
避免一边的概念直接污染另一边。

对两个知识系统而言，这不必实现为复杂同步服务。
一条稳定链接、明确的 canonical 声明、少量摘要字段，
就足以构成轻量的边界协议。
真正应避免的是无声复制：复制品最初最方便，
但它没有说明谁负责更新，也没有暴露何时开始过期。

## 一个区分：主题归属与证据管辖权

Corpus 过去已经意识到，过度结构性分类会增加归属负担，
而实际使用更接近功能性分类。
这次可以再向前一步：
文件位置不仅是功能分类，也是一种 **evidentiary jurisdiction（证据管辖权）**。

所谓证据管辖权，是一个系统对某类断言承担的默认责任：

1. **它允许什么成为事实。** 是可重跑结果、引用过的材料，
   还是当时真实存在过的感受与判断？
2. **它要求什么作为邻接证据。** 代码、数据和参数，
   还是时间线、反馈与认知变化？
3. **它怎样处理修订。** 覆盖旧结果、保留 provenance，
   还是允许不同阶段的自我并置？
4. **它面向谁开放。** 论文读者、未来合作者、Agent，
   还是首先面向未来的自己？
5. **它以什么方式失效。** 构建失败、数据过期、链接腐烂，
   还是语境消失、回顾时把过去重写得过于整齐？

按这个模型，Quarto 与 Corpus 的边界可以暂时这样描述。

### Quarto 管辖可复核的研究状态

Quarto 应成为研究定义、数据来源、分析代码、图、表、
方法限制和正式叙事的 canonical home。
它的核心契约是：结论尽量能追到输入、变换和版本，
展示内容与生成过程保持近距离。

一条记录若在回答「这个科学断言凭什么成立」，
或将被论文、报告、合作者与未来复算直接依赖，
就应跟随研究活动进入 Quarto。
这里的归属不取决于它是否写得正式，
而取决于它是否承担研究证据链的一部分。

### Corpus 管辖被经历过的研究

Corpus 不必因此清除所有科研痕迹。
它可以继续保存阅读进入个人判断的方式、
研究过程中的受挫与转向、工具为何被选择、
某种反复出现的认知模式，以及科研与生活怎样互相改变。

一条记录若在回答「我如何走到这个判断」，
它的首要证据往往是时间、处境与后续变化。
这类内容即使谈论文，也仍属于 Corpus 的自省与生命史，
不能只因主题含有 LSWT 就自动外迁。

### Dashboard 管辖当前承诺

Dashboard 则承担第三种责任：
当前哪些事仍在推进、下一步是什么、完成条件是什么。
它不应成为研究结论或长期反思的副本。
任务完成后，真正需要长期存在的证据分别回到 Quarto 或 Corpus；
Dashboard 只保留足以解释承诺变化的状态痕迹。

于是，三个系统并非按「工作 / 生活」切成互斥抽屉，
而是分别管辖可复核状态、被经历的意义和当前承诺。
同一事件可以在三处留下不同记录，
但每处记录回答的问题不同。

## 边界协议：不追求同步，追求可追溯

如果接受证据管辖权，迁移就不需要追求两库内容完全同步。
更轻的协议可能包含四条。

### 只指定一个 canonical body

科学定义、结果和方法正文只在 Quarto 维护完整版本；
Corpus 若需要引用，只保留解释本地意义所需的最短摘要与链接。
个人反思则反向保持在 Corpus，
Quarto 只在方法决策确实需要时引用其结论，不复制私人叙事。

### 让链接说明关系，而不只说明位置

链接旁边最好写清楚它为何存在：
`method definition`、`decision rationale`、`source record`、
`supersedes` 或 `reflection`。
一条带类型的关系比「相关链接」更能保存 archival bond。

### 在边界处翻译，不直接搬运语言

Quarto 中的 `probe`、`result`、`finding`、`draft`
未必与 Corpus 中同名状态含义一致。
跨库引用时，应把对方的状态翻译成本地可理解的句子，
而不是假设共享一个全局 ontology。

### 允许断开，但要留下断开的痕迹

如果某篇 Corpus 旧笔记被研究项目正式取代，
可以保留一行 `superseded by`，而非删除历史。
如果 Quarto 中某条探索被放弃，也应记录其停止条件，
避免未来只看到缺席，却不知道它是未做、失败还是主动降级。

这套协议的目标不是让两个仓库组成分布式数据库。
它只要求跨边界时保留足够的 provenance，
使未来的人与 Agent 能判断：正文在哪里、为何可信、
本地摘要是否过期，以及另一套系统为何以不同语言谈同一事件。

## 对那句 DoD 的一次改写

「Corpus 中没有关于科研工作的任何记录」有很强的执行推动力，
但它把主题边界写成了清除规则。
若想保留原意，同时减少误伤，可以改写为：

> Corpus 不再作为科研产物与科学结论的 canonical home；
> 可复核研究记录迁入 Quarto，Corpus 仅保留阅读、判断、
> 经历与系统自省所需要的研究痕迹，并以链接指向正式证据链。

这个版本比原句长，却明确了迁移对象、保留条件和跨库关系。
它也承认一个事实：研究不是生活之外的一种纯内容类型。
研究产物可以分离，研究如何改变一个人不能被完全剥离。

真正需要离开 Corpus 的，是承担科学真实性责任的正文；
需要留下的，是 Corpus 理解自身变化不可缺少的痕迹。

## 小结：边界保护的不是整齐，而是语境

bounded context 告诉我们，一个巨大统一模型会因多义词和不同责任而失真；
respect des fonds、original order 与 archival bond 提醒我们，
记录的意义依赖它与生成活动及邻近记录的关系；
records continuum 把创建、捕获、组织和共享看成重叠过程；
parallel provenance 允许同一事件拥有多个证据面；
information scent 则说明，稳定边界能让人提前知道该去哪里、相信什么。

由此看，科研迁出 Corpus 并不是一次文件清仓，
而是重新分配知识系统的证据管辖权。
Quarto 对可重跑的科学状态负责，Corpus 对被经历和内化的变化负责，
Dashboard 对当前承诺负责。三者可以互相引用，
却不需要争夺一份无所不包的主笔记。

好的知识架构不会收留所有东西。
它也不会因为分开而假装彼此无关。
它让每条记录待在最能保存其作证关系的地方，
再用足够窄、足够诚实的桥，把不同语境重新接起来。

笔记住在哪里，最终决定的不只是能否找到它，
还决定了我们拿它来证明什么。
