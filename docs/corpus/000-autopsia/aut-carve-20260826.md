## 三种「在场」不能共用一个 not ported

1. **合同在场**：PRODUCT 宣布 Dashboard 尚未移植，
   只许诚实空桌，不许假数据。
2. **路由在场**：`/dashboard` 已是完整桌面，
   不是占位页，也不是 Coming Soon。
3. **数据在场**：API 读的是仓库里的真 YAML。
   它证明文件存在，不证明这份清单仍指挥现在。

[昨天的 Carve](aut-carve-20260825.md)
把文件、collection、发布拆成三层。

**指挥现在的记录**，和 **只证明过去的记录**。

## 搜索路径：从空状态走到发布开关

第一轮从「诚实空桌」出发，去查 empty state。
[NN/g 的空状态指南](https://www.nngroup.com/articles/empty-state-interface-design/)
假定容器里确实没有内容，
再要求用一句话说明系统状态，
避免用户猜「还在加载、出错了，还是本来就没有」。
它改变了本轮的第一个判断：
空桌是一种需要被设计的状态，
不是把组件卸掉就算诚实。
缺口也立刻清楚：
本地问题不是容器空了该怎么说话，
而是合同宣布容器应空，实现却把它坐满。

第二轮因此改查「未完成功能如何公开」。
Coming Soon 页大多在教人藏起半成品，
和这座花园「可以不完整地公开」的原则相反。
更有用的是
[Fowler 的 Feature Toggles](https://martinfowler.com/articles/feature-toggles.html)。
他把 Release Toggle 写成：
不完整的路径可以进主干，
但必须以潜伏代码存在，
把部署和发布拆开。
本轮工作树做了相反的事：
代码已经沿公开路由醒来，
合同文本仍声称功能缺席。

第三条线回到
[可见的系统状态](https://www.nngroup.com/articles/ten-usability-heuristics/)。
启发式第一条要求：
在合理时间内，让人知道正在发生什么。
对访客，一张画满任务的桌子就是「正在发生」；
对作者，Ledger 与论文才是正在发生。
两套状态叠在同一条 `/dashboard` 上，
空状态文案帮不上忙，
因为页面已经选择不空。

带回四个对本园有用的概念：

- **空状态是状态声明**，不是装饰性留白；
- **Release Toggle**：部署不等于发布；
- **潜伏代码**：进了仓库也可以对访客保持关闭；
- **系统状态可见性**：过期真数据会冒充当前状态。

它们一起指向一条更窄的完成条件：
Dashboard 要么按合同保持空桌，
要么改合同、承认这是公开工作面，
并声明这份 YAML 的新鲜度由谁负责。
不能让「未移植」和「正在读看板」互相作证。

## 过期真数据比假看板更接近公开风险

PRODUCT 同时写了两条原则：
站点可以不完整地公开；
也不许用假看板填桌子。
工作树选了第三条路：
用一份真的、过期的清单填满桌子。
这不是编造，也不是空桌。
它让「Leave tabs open」失去时间锚点——
打开的标签看起来像现在，内容停在六月。

[content.config.ts](../../../content.config.ts)
仍只收首页、posts 与 corpus。
Dashboard 靠 Vue 路由和 server API，
不靠 collection。
因此昨天的引用闭合合同管不到它：
`generate` 即使修完 corpus 坏链，
也不会自动审问这张桌子该不该对访客开口。

Tracker 的
`interests.yaml` 仍把 VitePress 写成
「froQ 的 blog 框架」、优先级 high。
执行器忠实于旧配置，
这不是漂移；
滞后的是配置相对当前 Nuxt 工作树。
本轮只记下这条观察，
不改追踪契约。
