## 缘起

想要用 OpenHanako 代理群来做博客记录辅助和日程规划，不再依赖手动召唤 agent 问进度、写文件。

## 分工

讨论后确定的角色分配：

| Agent | 职责 | 主攻 corpus 层 |
|---|---|---|
| 毛毛 | 傍晚感性复盘，情绪温度记录 | putredo + vigil |
| 明 | 早检/晚检日程追踪，系统复盘 | autopsia + neoplasma |
| 花花 | 整合写入，博客写作辅助 | putredo + ingesta |

全层可写不设死区，日常积累自然触发。

## 日程时间线

- 09:30 早检（明发起）
- 23:00 晚检（明发起）
- 23:20 感性复盘（毛毛）
- 23:40 收尾写入 + putredo 归档（花花）

时间锚定在睡前，蛙蛙关电脑前看到归档完毕。

## 决策要点

- 去掉了旧版本的验证链阻塞机制，改为确认后写入
- YAML 从 links 格式简化为 notes 数组格式
- 群聊即共享内存缓冲区，不另开工作群
- corpus 写入走 docs/corpus/300-putredo/，文件名 put-YYYYMMDD.md
- cron 已由明锁定

## 感受

这次架构花了大概 40 分钟从零推到确认，节奏很顺。蛙蛙的「改了简化版」是关键：旧架构验证链的心智负担确实过大，去掉后整个流程从「过关」变成了「流水线」。明天 09:30 跑第一轮，看看实际效果。
