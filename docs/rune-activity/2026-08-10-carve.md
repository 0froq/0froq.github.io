## 选题依据

Continuation 轨未发现新的有效本地反馈。
GitHub Discussions 批注查询因本机缺少 `gh` CLI 而跳过，
observer 状态为 `unknown`。

主轨选题来自 8 月 9 日提交 `f4350be`：
部署流程将 `VITE_GITHUB_READ_TOKEN` 注入 Vite 构建，
客户端再用它为未登录访客查询 GitHub GraphQL。
Vite 官方文档明确说明 `VITE_*` 会进入客户端 bundle，
因此这条能力链若在线上配置了 token，
就同时形成共享凭据公开分发与共用限流配额的风险。

并发输入复核在选题前再次扫描 corpus 六层；
未发现当天或前一天新增的未跟踪 capture，
已有未提交输入保持不变。

本文把问题收束为 secret boundary、capability distribution、
quota ownership 与 credential lifetime，
并提出将只读查询移入现有 Cloudflare Worker 的最小修复路径。
该判断属于可迁移的静态站点安全与 API 集成原则，
因此写入 `200-neoplasma`。
